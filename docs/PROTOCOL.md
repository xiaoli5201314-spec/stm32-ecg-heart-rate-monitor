# 二进制协议：版本 1

本说明以 [frame_protocol.h](../firmware/include/frame_protocol.h)、[frame_protocol.c](../firmware/src/frame_protocol.c)、[设备发送实现](../firmware/src/ecg_pipeline.c) 和 [协议测试](../firmware/test/test_protocol.c) 为准。它描述实际字节格式，不表示已有 MFC 上位机或完整双向命令系统。

## 1. 帧封装

```text
A5 5A TYPE LEN SEQ_lo SEQ_hi PAYLOAD... CRC_lo CRC_hi
```

| 字节偏移 | 大小 | 字段 | 实际规则 |
|---|---|---|---|
| 0 | 1 | HDR0 | 固定 `0xA5` |
| 1 | 1 | HDR1 | 固定 `0x5A` |
| 2 | 1 | TYPE | 高四位版本 `1`，低四位类型；`(1 << 4) \| (type & 0x0F)` |
| 3 | 1 | LEN | 载荷字节数，0..255 |
| 4 | 2 | SEQ | `uint16` 小端 |
| 6 | LEN | PAYLOAD | 依类型解释 |
| 6+LEN | 2 | CRC16 | 校验值小端，低字节先发 |

固定开销 8 字节，最大整帧 263 字节。所有多字节整数按小端逐字节写入；有符号字段以二进制补码解释，不能直接发送 C 结构体内存布局。

### 帧类型和完成度

| 低四位 | 线上 TYPE 字节 | 名称 | 当前能力 |
|---|---|---|---|
| `0x1` | `0x11` | `ADC_PACK12` | 波形组帧与解析 |
| `0x2` | `0x12` | `ADC_DELTA` | 波形组帧与解析 |
| `0x3` | `0x13` | `HR_REPORT` | 组帧、解析、设备自动上报 |
| `0x4` | `0x14` | `STATUS` | 组帧、设备自动上报；无专用载荷解析函数 |
| `0x5` | `0x15` | `CALIBRATION` | 组帧/解析工具；设备不会自动发送 |
| `0x6` | `0x16` | `ACK` | 3 字节载荷构造工具；没有设备确认流程或专用解析函数 |
| `0x7` | `0x17` | `NAK` | 仅类型枚举，没有载荷定义或处理器 |
| `0x8` | `0x18` | `HOST_CMD` | 仅类型枚举，没有命令格式或处理器 |

## 2. CRC 的精确定义

实现为 CRC-16/CCITT-FALSE：

```text
width   = 16
poly    = 0x1021
init    = 0xFFFF
refin   = false
refout  = false
xorout  = 0x0000
coverage = TYPE, LEN, SEQ_lo, SEQ_hi, 全部 PAYLOAD
```

输入地址 `&frame[2]`，输入长度 `4 + LEN`。同步字 `A5 5A` 和 CRC 字节本身不参与校验。CRC 运算按高位处理，不因最终小端发送而变成反射型算法。

源码中的无查表参考算法可表示为：

```text
crc = 0xFFFF
for byte in TYPE..PAYLOAD:
    crc ^= byte << 8
    repeat 8 times:
        if crc & 0x8000:
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF
        else:
            crc = (crc << 1) & 0xFFFF
```

协议测试的标准向量是 ASCII `123456789`，CRC 为 `0x29B1`。该值不是任意帧的校验值。查表版与参考版都有测试；查表版的首次惰性初始化没有线程同步，不能假定任意多线程并发首次调用安全。

## 3. 波形载荷

两种波形载荷均以 `N_lo N_hi` 开头，表示样本数。组帧 API 接受 1..64 点，设备默认每 24 点发一帧。

**单位为滤波后的电极参考整数微伏 `uV`，不是原始 12-bit ADC 码值。** 设备先将浮点值四舍五入并饱和到 `int16` 范围 `[-32768,32767]`，然后选择编码。因此编码对输入整数无损，不等于整条链对原始 ADC 数据无损。

### 3.1 PACK12

可表示的实际闭区间是 `[-2048,2047] uV`，偏移二进制：

```text
code = value_uv + 2048
```

对于两个 12 位码 `a`、`b`：

```text
byte0 = a & 0xFF
byte1 = ((a >> 8) & 0x0F) | ((b & 0x0F) << 4)
byte2 = (b >> 4) & 0xFF
```

奇数个样本的最后一个码单独占 2 字节，第二字节高四位写 0。

```text
编码字节数 = 3 * floor(N/2) + 2 * (N mod 2)
载荷字节数 = 2 + 编码字节数
整帧字节数 = 8 + 载荷字节数
```

示例 `[-2048,2047]` 对应码 `[0,4095]`，完整载荷为：

```text
02 00 00 F0 FF
^^^^^ 样本数 2；后三字节为打包码
```

默认 24 点：36 字节编码数据 + 2 字节数量 = 38 字节载荷；**完整 PACK12 帧为 46 字节**，不能把 36 字节编码数据称为完整载荷。

### 3.2 DELTA

```text
N_lo N_hi base_lo base_hi 后续差分或转义...
```

首个样本是小端有符号 `int16`。后续：

- 差分 `current - previous` 在 `[-127,127]` 内：一个有符号 `int8`。
- 其他差分：`80` 后跟当前样本的绝对 `int16` 值，小端。
- `-128` 也必须转义；`0x80` 不是普通差分。

设后续样本中有 `E` 次转义：

```text
编码字节数 = 2 + (N - 1) + 2E
载荷字节数 = N + 3 + 2E
整帧字节数 = N + 11 + 2E
```

示例 `[100,105,-1000]`：

```text
03 00 64 00 05 80 18 FC
数量3 基准100 +5 转义 绝对值-1000
```

默认 24 点且无转义时，27 字节载荷、35 字节整帧；每次转义额外加 2 字节。不能给所有波形固定套用某次测试的 DELTA 帧长。

底层解码器对累加超出 `int16` 的值做饱和，对截断转义停止解码；载荷解析函数再检查恢复的样本数是否足够。

### 3.3 自动选择规则

`ecg_frame_build_samples()` 比较两种完整载荷长度：

1. 任一样本超出 PACK12 范围，则 PACK12 不可用，选择 DELTA。
2. 两者可用且 DELTA 严格更短，选择 DELTA。
3. 两者长度相等或 PACK12 更短，选择 PACK12。

波形 API 名称虽然带 `ADC`，不能改变其微伏载荷语义。直接调用底层 `ecg_pack12()` 只会保留输入低 12 位，不执行有符号范围检查或微伏偏移；应由上层组帧 API 完成这些约束。

## 4. 心率报告：9 字节

偏移相对于 PAYLOAD：

| 偏移 | 类型 | 字段 | 单位/语义 |
|---|---|---|---|
| 0 | `uint8` | flags | 设备 bit0 = RR 已接纳；bit1 = 算法标记的 RR 异常 |
| 1 | `int16 LE` | bpm_x10 | 瞬时 BPM × 10 |
| 3 | `int16 LE` | bpm_avg_x10 | 最近有效 RR 中位数所对应的 BPM × 10，不是 BPM 算术平均 |
| 5 | `uint16 LE` | rr_ms | R-R 间期，毫秒 |
| 7 | `uint8` | quality | 0..100 的 SQI 启发式指标，不是医学置信度 |
| 8 | `uint8` | reserved | 设备写 0 |

设备未把 `ECG_BEAT_RECOVERED` 单独映射到线上标志。第一搏尚无 RR，可能上报初始心率先验，接收方应检查 bit0。

### 完整字节示例

使用 `test_report_frames()` 的测试夹具：序号 5、flags `03`、瞬时 72.3 BPM、中位 RR 心率 71.8 BPM、RR 834 ms、SQI 96、reserved 0。根据上述源码算法得到：

```text
A5 5A 13 09 05 00 03 D3 02 CE 02 42 03 60 00 67 78
```

CRC 输入是 `13 09 05 00 03 D3 02 CE 02 42 03 60 00`，计算值 `0x7867`，线上为 `67 78`。这是字段编解码示例，不是某次真实采集；夹具的 `flags=03` 用于字段往返测试，不表示正常设备会把“RR 接纳”和“RR 异常”同时置位。

## 5. 状态报告：7 字节

| 偏移 | 类型 | 字段 | 当前语义 |
|---|---|---|---|
| 0 | `uint8` | flags | 未定义各 bit 的有效业务含义；设备初始化为 0，未更新导联脱落/削顶状态 |
| 1 | `uint16 LE` | ring_fill | ADC 采样环当前剩余元素数，不是字节数 |
| 3 | `uint32 LE` | dropped | ADC 采样环拒绝的样本累计数 |

`dropped` 不包含所有 UART 丢字节、未交付的 DMA 尾块或其他错误。不能据此宣称完整数据链无丢失。

## 6. 标定报告：16 字节

| 偏移 | 类型 | 字段 | 缩放/单位 |
|---|---|---|---|
| 0 | `int32 LE` | slope_x1000 | counts/mV × 1000 |
| 4 | `int32 LE` | intercept_counts_x1000 | counts × 1000 |
| 8 | `int16 LE` | nonlinearity_x100 | 非线性百分数 × 100 |
| 10 | `int16 LE` | afe_gain_x10 | 增益 V/V × 10 |
| 12 | `int16 LE` | r2_x10000 | R² × 10000 |
| 14 | `uint8` | n_points | 标定点数 |
| 15 | `uint8` | flags | bit0 = valid |

构造器直接写调用方提供的定点整数，不负责从 `ecg_cal_t` 自动缩放或饱和。构造器/解析器存在不代表标定采集、存储或自动发送流程已实现。

## 7. ACK 与序号

ACK 载荷：

```text
acked_type acked_seq_lo acked_seq_hi
```

`acked_type` 是调用者提供的一个字节。测试使用低四位类型值 `ECG_FRAME_HOST_CMD = 0x08`；构造器不替调用者添加版本位。NAK 不能按猜测套用相同载荷。

设备对已构造的上行帧使用同一个 `uint16` 序号计数器，跨类型递增并在 65535 后回到 0；发送排队失败也可能使线上序号出现间隔。序号只能辅助发现缺帧/重复，未实现重传、确认闭环、会话编号或认证。

## 8. 接收状态机和集成注意事项

接收同步器保存最多 263 字节的候选窗口，跨调用保留半包。合法完整帧消费整帧；无效同步字、版本或 CRC 候选从窗口滑动 1 字节再找同步。

需要保留以下限制：

- `LEN` 是单字节，250 等值属于合法长度；错误的大长度会等待足够后续字节，**没有超时或流结束时强制刷新接口**。有界内存不等于有限时间恢复。
- 帧解码验证同步字、版本和 CRC，但不验证低四位类型是否已定义；必须在业务层选择载荷解析器。
- `ecg_frame_decode()` 接受后面还有额外字节的输入，调用方要自行使用 `8 + LEN` 确定消费长度。
- 波形载荷解析器允许额外编码样本/尾随数据，只检查是否恢复了至少声明数量；成功不等于严格验证每个载荷字节。
- `ecg_frame_sync_feed_buf()` 在输出数组达到 `max_frames` 后仍消费所有输入，额外完整帧进入临时缓冲而被丢弃。需要逐帧回调时可使用逐字节 `feed()`，不能把小输出数组当作自动背压。
- CRC 用于偶发错误检测，不是防篡改、加密、身份认证或人体安全措施。

协议测试覆盖特定坏 CRC、坏长度、随机垃圾和半包/粘包场景；不能扩大成“任何损坏下都立即恢复”或“随机输入绝无假帧”的保证。
