# 设计文档 · STM32 心电信号采集与心率分析系统

本文是 `stm32-ecg-heart-rate-monitor` 的独立设计说明，记录**每个技术决策的取舍依据**，
以及支撑这些决策的实测数据。所有数字都来自本仓库真实编译运行的结果，复现命令见文末。

- 采样率 250 Hz / 12 bit ADC / 单通道肢体导联
- 目标 MCU：STM32F103C8T6（Cortex-M3，72 MHz）
- 固件语言：纯 C99，可在 PC 上用 gcc 编译并跑完整单元测试

---

## 1. 系统分层

```
   ┌──────────────── 模拟域 ────────────────┐   ┌──────────── 数字域 ────────────┐
   │ 电极 → 保护 → 仪表放大 → 高通×2 → 低通 │   │ ADC → DMA → 环形缓冲 → 滤波链 │
   │        ↑ 右腿驱动   ↑ 基准搬移 50Hz 陷波│   │  → QRS 检测 → 帧协议 → UART   │
   └────────────────────────────────────────┘   └────────────────────────────────┘
```

代码按“**纯算法 / 设备集成 / 硬件抽象**”三层切开，这是本仓库最重要的架构决策：

| 层 | 文件 | 是否依赖硬件 | 是否有测试 |
|---|---|---|---|
| 纯算法 | `src/iir_notch.c`、`src/savgol.c`、`src/frame_protocol.c`、`src/heart_rate.c`、`src/ring_buffer.c` | 否 | 是，逐函数覆盖 |
| 设备集成 | `src/ecg_pipeline.c` | 只通过 `hal.h` 的操作表 | 是，端到端回环 |
| 硬件抽象 | `include/hal.h`、`hal/hal_stub.c` | 是（PC 桩）/ 目标板另实现 | 是，桩本身被测试 |

这么切的好处：**换 MCU 只需要重写 `hal_stub.c` 对应的那一张操作表**，
4 个算法文件一行都不用动；同时因为算法层没有硬件依赖，它们可以在 PC 上
用 gcc + 单元测试逐条验证，而不是靠“烧进去看一眼波形”。

## 2. 采样时序：为什么必须是定时器触发 + DMA

### 2.1 三种采样方式的对比

| 方案 | 采样间隔抖动 | CPU 占用 | 结论 |
|---|---|---|---|
| 主循环里 `while(1){ HAL_ADC_GetValue(); Delay(); }` | 取决于循环里其它代码，抖动可达毫秒级 | 高 | 不可用 |
| ADC 连续转换 + 轮询读取 | 抖动小，但读取时刻不确定 | 高 | 不建议 |
| **TIM 更新事件触发 ADC + DMA 循环搬运** | **由硬件时钟决定，抖动 = 0** | **≈0（只有半满/全满中断）** | **本项目采用** |

心率分析对采样等距性的要求是硬的：R-R 间期误差与 BPM 误差的关系是

```
BPM = 60 · fs / RR_samples      →      ΔBPM/BPM = ΔRR/RR
```

要在 180 BPM（RR = 83 个采样点）下把误差压到 1 BPM 以内，
R 峰定位误差必须小于 0.5 个采样点。任何由软件调度引入的采样抖动
都会直接变成 BPM 误差，所以采样时钟必须与 CPU 解耦。

### 2.2 定时器参数

```
TIM2 时钟     72 MHz
预分频        72e6 / (250 Hz × 1000) − 1 = 287      → 计数时钟 250 kHz
自动重装      999                                    → 更新事件 250 Hz
触发输出      TRGO = Update，ADC 外部触发源 = TIM2_TRGO
每次触发      ADC1 规则组单通道，12 bit
DMA1_CH1      循环模式，半满/全满各产生一次中断
```

`ECG_TIM2_PRESCALER` / `ECG_TIM2_PERIOD` 在 `include/ecg_config.h` 里由
编译期表达式算出，改采样率只需要改 `ECG_SAMPLE_RATE_HZ` 一个宏。

### 2.3 DMA 缓冲与环形缓冲的分工

```
DMA 缓冲区（128 个 uint16_t，循环）
   [0 .. 63]   半满中断 → ISR 把前 64 个搬进环形缓冲
   [64 .. 127] 全满中断 → ISR 把后 64 个搬进环形缓冲

环形缓冲（1024 个 uint16_t，2 的幂）
   生产者 = DMA 中断，消费者 = 主循环，无锁
```

DMA 缓冲区只有 128 点（512 ms），因为它是**双缓冲语义**：中断必须在下一次
半满之前把数据搬走；环形缓冲有 1024 点（4 s），给主循环留出足够的余量。
实测 60 s 连续采集：`ISR 块数 234`、`采样点 14976`、`丢点 0`、`环形溢出 0`。

## 3. 无锁环形缓冲（`ring_buffer.c`）

### 3.1 为什么可以无锁

单生产者单消费者（SPSC）模型下，`head` 只被生产者写、`tail` 只被消费者写，
两边各自只需要保证“数据先写好，索引后发布”。因此：

- 不需要关中断，**不会破坏 250 Hz 采样节拍**
- 不需要互斥量，**不依赖 RTOS**
- 索引用 `uint32_t` 单调递增、写入时 `& mask` 取模，天然处理回绕，
  不需要“牺牲一个槽位区分空满”的技巧

### 3.2 内存序

| 工具链 | 机制 |
|---|---|
| GCC / Clang（本仓库测试用） | `__atomic_load_n(..., __ATOMIC_ACQUIRE)` / `__atomic_store_n(..., __ATOMIC_RELEASE)` |
| Keil / IAR（未定义 `__GNUC__`） | `volatile` + 编译器屏障 |

单核 Cortex-M 上 DMA 写入与 CPU 读取本来就由总线序保证，编译器屏障足够；
用 C11 原子内建只是为了在 PC 上跑双线程压力测试时结果可信。

### 3.3 实测

```
双线程 SPSC 压力测试        400000 个样本，顺序错误 0
慢消费者场景                高水位 64/64，被拒绝 5544 个样本（计数准确）
```

缓冲区是**泛型**的：`elem_size` 在运行时给出，内部逐元素 `memcpy`。
这样同一份代码既服务于 `uint16_t` 的采样环，也服务于 `uint8_t` 的串口发送环，
而且避免了把字节缓冲区强转成 `uint16_t*` 可能带来的对齐与严格别名问题。

## 4. 50 Hz 工频陷波器（`iir_notch.c`）

### 4.1 为什么选 IIR 而不是 FIR

| | FIR 陷波 | **IIR 陷波（本项目）** |
|---|---|---|
| 达到 −40 dB 陷波深度所需阶数 | 约 200~400 阶（fs/Δf 量级） | **2 阶双二阶** |
| 单样本运算量 @250 Hz | 数百次乘加 | **5 次乘加** |
| 群延迟 | 100~200 个采样点（0.4~0.8 s，不可接受） | **约 0.15 个采样点** |
| 相位 | 严格线性 | 非线性，但陷波带宽很窄，对 QRS 影响可忽略 |
| 系数稳定性 | 绝对稳定 | 需要检查极点半径（本项目 0.942，稳定） |

心电 QRS 的陡峭沿集中在 10~40 Hz，而 FIR 陷波要把 50 Hz 压 40 dB
必然需要很长的冲激响应，群延迟会把 QRS 拖成“馒头波”，
这对峰值检测和波形显示都是灾难。所以**窄带干扰用 IIR 陷波，宽带噪声用
Savitzky-Golay（线性相位）**，两者分工是这个滤波器组的核心思路。

### 4.2 系数推导

模拟原型（在 w0 处为零点、Q 决定带宽的对称陷波）：

```
H(s) = (s² + w0²) / (s² + (w0/Q)·s + w0²)
```

双线性变换（带频率预畸变，保证数字零点精确落在 50.00 Hz 而不是 50.6 Hz）：

```
s = 2·fs·(1 − z⁻¹)/(1 + z⁻¹)
K = tan(π·f0/fs)                      … 预畸变因子
```

代入并归一化，得到工程上常用的闭式解（令 `w0_d = 2π·f0/fs`）：

```
alpha = sin(w0_d) / (2Q)
1 + alpha = 1.0594410323

b0 =  1 / (1+alpha)                  =  0.943893968179
b1 = −2cos(w0_d) / (1+alpha)         = −0.583358554111
b2 =  1 / (1+alpha)                  =  0.943893968179
a0 =  1
a1 = −2cos(w0_d) / (1+alpha)         = −0.583358554111
a2 = (1−alpha) / (1+alpha)           =  0.887787936359
```

代入本项目实际参数 **fs = 250 Hz、f0 = 50 Hz、Q = 8**：

```
w0_d  = 2π × 50 / 250 = 1.2566370614 rad
cos   = 0.3090169944        sin = 0.9510565163
alpha = 0.9510565163 / 16 = 0.0594410323
```

等价于 MATLAB：

```matlab
wo = 50/(250/2);  bw = wo/8;  [b,a] = iirnotch(wo,bw);
```

极点半径 `sqrt(a2) = 0.9422241`，与零点同角度、在单位圆内 → 稳定。
零点精确落在单位圆上 → 理论上 50.00 Hz 处增益为 0。

**为什么 Q = 8**：单级 −3 dB 陷波带宽 = f0/Q = 6.25 Hz。
Q 太小（宽带）会削掉 QRS 的 40~60 Hz 分量；Q 太大（窄带）则电网频率
漂移 ±0.2 Hz 时衰减立刻掉到 10 dB 以下。Q = 8 对应 ±3.1 Hz 半带宽，
既覆盖工频漂移，又不碰心电诊断带宽。

### 4.3 级联：用两级换取深度和漂移容限

单级陷波在 50.00 Hz 处是理想零点，但偏离 0.2 Hz 衰减就掉到 −24 dB。
**两级相同双二阶级联**的实测效果：

| 频率 | 单级 | 两级级联 |
|---|---|---|
| 49.00 Hz | −8.16 dB | −16.32 dB |
| 49.50 Hz | −13.67 dB | **−27.34 dB** |
| 49.80 Hz | −21.5 dB | **−42.96 dB** |
| **50.00 Hz** | **−256.38 dB** | **−256.57 dB** |
| 50.20 Hz | −21.5 dB | −42.99 dB |
| 50.50 Hz | −13.70 dB | −27.41 dB |
| 51.00 Hz | −8.22 dB | −16.44 dB |

效果：**整个 ±0.5 Hz 漂移带内最差衰减 −27.34 dB**（要求 ≥20 dB），
而通带几乎无损：

| 频率 | 0.5 | 1 | 5 | 10 | 20 | 40 | 75 | 100 Hz |
|---|---|---|---|---|---|---|---|---|
| 衰减 | −0.000 | −0.000 | −0.001 | −0.004 | −0.022 | −0.415 | −0.072 | −0.008 dB |

代价：2 个双二阶 = 10 次乘加/样本，在 72 MHz 的 M3 上约 1.4 µs/样本，
占 4 ms 采样周期的 0.035%。可以忽略。

### 4.4 定点/浮点实现

采用**转置直接 II 型（transposed direct form II）**：只要 2 个状态变量，
且中间变量不经过差分放大，舍入噪声最小：

```
y  = b0·x + z1
z1 = b1·x − a1·y + z2
z2 = b2·x − a2·y
```

`ecg_real_t` 默认是 `double`；在带 FPU 的 Cortex-M4F/M7 上定义
`ECG_USE_SINGLE_PRECISION` 即可整体切成 `float`，算法代码无需改动。

## 5. Savitzky-Golay 最小二乘平滑（`savgol.c`）

### 5.1 为什么不用普通滑动平均

滑动平均在频域是 sinc，主瓣宽、旁瓣高，会把 QRS 的陡峭沿“抹圆”。
Savitzky-Golay 在窗口内**拟合一个 p 阶多项式**，然后取拟合曲线在输出点的值。
由于 p 阶多项式被完全保真，它能在压噪声的同时保留波形的**高阶矩**
（峰值高度、拐点位置），这正是 QRS 检测需要的。

### 5.2 从（阶数, 窗长）自动算卷积核

这是本仓库要求“不允许硬编码系数表”的部分，实现思路如下。

窗口长度 `L = 2m+1`，把横坐标归一化到 `[−1, 1]`：

```
x_i = (i − m)/m ,      i = 0 … L−1
```

在窗口内做 p 阶最小二乘拟合：

```
min_c  Σ_{i=0..L−1} ( y_i − Σ_{k=0..p} c_k · x_i^k )²
```

写成矩阵形式（A 为 Vandermonde 矩阵，`A[i][k] = x_i^k`）：

```
A·c = y   （超定）  ⇒  c = (AᵀA)⁻¹ Aᵀ y
```

输出是拟合多项式在 `x_pos` 处的值：

```
y_out = p(x_pos) = e_posᵀ · c = e_posᵀ (AᵀA)⁻¹ Aᵀ y = hᵀ y
其中  h = A (AᵀA)⁻¹ e_pos ,   e_pos = [1, x_pos, …, x_pos^p]ᵀ
```

于是**卷积核 h 就是解一个 (p+1)×(p+1) 的对称线性方程组**：

```
(AᵀA) u = e_pos        ← Gauss-Jordan 消元 + 部分主元
h_i = Σ_k A[i][k] · u_k
```

代码里 `ecg_savgol_design_at()` 就实现了这两步，`ecg_savgol_design()` 只是
令 `x_pos = 0`（窗口中心）的特例。

**两个数值细节**（不做的话 6 阶 41 点会直接崩）：

1. **横坐标按 m 归一化**。不归一化时 Gram 矩阵元素是 `Σ i^(k+l)`，
   值域跨十几个数量级，条件数 ~m^(2p)；归一化后 `|x| ≤ 1`，
   条件数下降多个数量级，double 下 6 阶/41 点仍稳定。
2. **核归一化到 Σh = 1**。数学上恒成立（拟合能精确复现常数），
   浮点下强制一次，保证直流增益精确为 1.0000。

### 5.3 正确性验证（不依赖任何第三方系数表）

| 验证项 | 结果 |
|---|---|
| 0 阶退化为滑动平均 | `h[i] = 1/L`，误差 < 1e-12 |
| 2 阶 5 点 = 教科书结果 `[−3,12,17,12,−3]/35` | 误差 < 1e-12 |
| 3 阶 7 点 = 教科书结果 `[−2,3,6,7,6,3,−2]/21` | 误差 < 1e-12 |
| 全网格（0~6 阶 × 全奇数窗长）Σh = 1 | 全部 < 1e-10 |
| 核对称性 `h[j] = h[L−1−j]` | 全部 < 1e-12 |
| **多项式复现**：0~4 阶多项式输入，输出与输入逐点相等 | 0 阶 8.9e-16，4 阶 3.1e-05 |
| 白噪声增益 = `sqrt(Σh²)` | 实测 0.4553 vs 预测 0.4555 |
| 流式实现与整段实现一致性 | 全参数组合 < 1e-9 |

### 5.4 边缘处理

信号开头/结尾不足一个窗口时，**不丢弃也不补零**，而是用“收缩窗口 +
重新定位输出点”的方式：第 i 个输出点用长度 `2i+1` 的窗口、在窗口中心求值。
这样 `ecg_savgol_apply()` 的输出长度与输入相同，且首尾样本也经过滤波
（否则记录开头的第一个 R 波会被截断，R 峰检测会漏一个心搏）。

### 5.5 参数扫描：阶数 × 窗长的取舍

在 72 BPM、30 µV rms 白噪声、σ_R = 15 ms 的合成心电上逐点实测
（`test_filters.c::test_sg_parameter_sweep`，共 34 组）：

- **noise[dB]**：白噪声抑制量，等于 −20·log10(sqrt(Σh²))
- **peak_meas[%]**：QRS 峰高保持率（滤波后/滤波前）
- **distort[%]**：滤波对**无噪**心电造成的波形失真（RMS / R 波幅度）
- **error[%]**：滤波后含噪信号与无噪真值的总误差（RMS / R 波幅度）

代表性数据（完整表由测试程序打印）：

| 阶数 | 窗长 | −3dB | 噪声抑制 | 峰值保持 | 波形失真 | 总误差 |
|---|---|---|---|---|---|---|
| 2 | 5 | 59.5 Hz | 3.14 dB | 99.89 % | 0.024 % | 2.089 % |
| 2 | 9 | 30.5 Hz | 5.93 dB | 98.70 % | 0.289 % | 1.540 % |
| 2 | 11 | 24.7 Hz | 6.83 dB | 97.32 % | 0.599 % | 1.490 % |
| 2 | 15 | 18.0 Hz | 8.21 dB | 92.39 % | 1.685 % | 2.050 % |
| 2 | 25 | 10.7 Hz | 10.45 dB | 68.45 % | 6.531 % | 6.586 % |
| 4 | 5 | 125.0 Hz | 0.00 dB | 100.00 % | 0.000 % | 3.002 % |
| 4 | 11 | 40.4 Hz | 4.77 dB | 99.81 % | 0.057 % | 1.727 % |
| 4 | 15 | 29.0 Hz | 6.21 dB | 99.17 % | 0.236 % | 1.484 % |
| **4** | **17** | **25.4 Hz** | **6.77 dB** | **98.58 %** | **0.401 %** | **1.431 %** |
| 4 | 21 | 20.5 Hz | 7.72 dB | 96.40 % | 0.973 % | 1.575 % |
| 4 | 31 | 13.8 Hz | 9.43 dB | 81.50 % | 4.102 % | 4.220 % |

**两个重要观察：**

1. **偶数阶和它 +1 的奇数阶结果完全相同**（2 阶 ≡ 3 阶，4 阶 ≡ 5 阶）。
   因为输出点在窗口中心 x = 0，奇次项对 p(0) 的贡献为零——这不是巧合，
   而是最小二乘拟合的对称性结论。
2. **窗长比阶数重要得多**。窗长决定噪声抑制和峰值保持的取舍，
   阶数只影响对波形曲率的拟合能力。窗长从 11 加到 25，噪声抑制只多
   3.6 dB，峰值保持却从 97% 掉到 68%——这是典型的赔本买卖。

**选定参数：4 阶 / 17 点**。选取准则是「在峰值保持 ≥95% 的约束下
最小化总误差」，扫描出的全局最优正是这一组（误差 1.431%）。
4 阶比 2 阶在同窗长下有更好的曲率拟合，失真反而更低（0.401% vs 0.599%）。
17 点窗在 250 Hz 下对应 68 ms，群延迟 8 点 = 32 ms，
远小于 QRS 时限（80~100 ms），不会影响 R 峰定位（R 峰由检测器在
滤波后信号上二次定位，32 ms 固定延迟在 R-R 差分中自动抵消）。

## 6. 基线漂移抑制与高通拐点的取舍

心电的 R、T、P 波面积**不相互抵消**：以本项目的合成波形为例，
每个心搏的净面积对应约 **+88 µV 的直流分量**。任何高通滤波器都会把这个
分量去掉，表现为等电位线整体下移——这正是“监护模式（0.5 Hz）与诊断模式
（0.05 Hz）”差异的物理来源。

实测不同高通拐点（2 极点，`tools/verify_filters.py` 第 [5b] 节）：

| 高通拐点 | 残余呼吸漂移 (rms) | R 波幅度保持 |
|---|---|---|
| 0.05 Hz（诊断） | 402.70 µV | 97.63 % |
| 0.20 Hz | 252.90 µV | 95.19 % |
| 0.35 Hz | 141.93 µV | 92.48 % |
| **0.50 Hz（本项目）** | **84.99 µV** | **89.73 %** |
| 1.00 Hz | 25.48 µV | 81.67 % |

**决策：0.5 Hz / 2 极点。** 理由：

1. 0.5 Hz 是 IEC 60601-2-27 允许的监护模式高通拐点，合规；
2. 呼吸漂移（0.2~0.35 Hz）被压低 14 dB，波形不会被漂移顶出显示窗口；
3. 代价是 R 波**视在幅度**下降约 10%——这是监护模式高通的固有代价，
   不是陷波器或 SG 的缺陷（SG 单独作用时峰值保持 98.58%）。
   如果同一份固件要用于诊断模式，只需把 `ECG_BASELINE_HP_HZ`
   改成 0.05 并把 `ECG_BASELINE_HP_SECTIONS` 改成 1，实测能换回
   8 个百分点的幅度保持，代价是漂移抑制从 14 dB 掉到 0.5 dB。

## 7. QRS 检测与心率统计（`heart_rate.c`）

### 7.1 检测链

```
x[n] → 5 点导数 → 平方 → 150 ms 滑动积分 → 自适应阈值 → 不应期/T 波判别
     → R 峰二次定位 → R-R 有效性校验 → 中位数 RR → BPM
```

### 7.2 为什么用 5 点导数而不是 2 点差分

5 点导数 `d[n] = (2x[n] + x[n−1] − x[n−3] − 2x[n−4]) / 8` 在直流和 Nyquist
处都有零点，通带峰值约在 0.16·fs（250 Hz 下约 40 Hz），正好覆盖 QRS 斜率
能量。**2 点差分 `x[n] − x[n−2]` 的通带一直顶到 Nyquist**，会把
“R→S 下降沿”和“S→等电位回升”变成两个独立的包络极大值，
第二个极大值落在不应期内被丢弃，却会被当成噪声喂进噪声估计，
把自适应阈值抬高。实测：改用 5 点导数后信号质量指数从 57 提升到 **99**。

### 7.3 自适应阈值

包络每次出现局部极大值时更新两个电平：

```
spki = 0.125·peak + 0.875·spki      （peak ≥ 阈值，判为信号）
npki = 0.125·peak + 0.875·npki      （peak <  阈值，判为噪声）
thr  = npki + 0.25·(spki − npki)
```

**噪声估计的门控**：R 峰之后 360 ms 内的包络极大值（QRS 肩部、T 波）
一律不参与 `npki` 更新——它们的幅度比真实噪声底高一个数量级。
门控上限同时被限制为当前 RR 中位数的一半，保证高心率时仍有样本
参与噪声估计。这是把 SQI 从 69 拉到 99 的关键。

若连续 `1.66 × RR_median` 没有检测到心搏，阈值临时减半（search-back），
用于找回因电极移动导致幅度塌陷的心搏。

### 7.4 异常值剔除

三层保护，实测有效：

1. **不应期**：R 峰后 200 ms 内的任何包络极大值直接丢弃。
   实测 60 BPM + 2 mV 肌电尖峰（落在 R 峰后 100 ms）：
   最小 RR = 250 采样点（1000 ms），**0 次不应期违规**。
2. **生理范围**：RR < 300 ms（>200 BPM）或 > 2000 ms（<30 BPM）判为伪迹，
   不计入 RR 序列，并把该候选点计入噪声估计。
3. **异位搏动识别**：`|RR − RR_median| > 40% · RR_median` 标记为异位，
   **不进入 RR 序列**（因此不污染中位数），但仍用于后续 R 峰定位。
   实测 3 mV 电极移动伪迹：1 次异位被标记，稳态 BPM 误差 0.000。

**一个必须避免的陷阱**：异位判据不能在拿到前几个真实 RR 之前生效。
初始 `RR_median` 先验是 75 BPM（200 点），若从第一拍就做异位判据，
那么 45 BPM（RR = 333 点，偏差 66%）和 150 BPM（RR = 100 点，偏差 50%）
起搏的 RR 会**永远被判为异位**，`RR_median` 永远不更新，BPM 卡死在 75。
本实现要求 `rr_series_count ≥ 3` 之后才启用异位判据，解决了这个死锁。

## 8. 增益与线性度标定（`ecg_pipeline.c`）

### 8.1 方法

1 mV 标准方波从**交流耦合网络之后**注入（真实前端就是这么设计的——
避免方波被 0.5 Hz 高通削顶），依次施加多档峰峰值，
每档用「3 点中值滤波 + 均值」测出高、低平台的 ADC 码值差：

```
counts_pp = mean_median(高平台) − mean_median(低平台)
```

对 (mV_pp, counts_pp) 做最小二乘直线拟合 `counts = a·mv + b`：

```
a = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)
b = (Σy − a·Σx) / n
```

派生指标：

```
模拟增益      G   = a · LSB_µV / 1000        [V/V]
电极分辨率    µV/LSB = 1000 / a
线性度误差    NL  = max|y − fit| / (y_max − y_min) × 100%  （满量程百分比）
拟合优度      R²  = 1 − SS_res / SS_tot
```

### 8.2 实测（4 档：0.5 / 1.0 / 1.5 / 2.0 mVpp，每档 256 点，10 µV rms 通道噪声）

| 输入 | 测得码值差 |
|---|---|
| 0.5 mVpp | 620.0 counts |
| 1.0 mVpp | 1242.0 counts |
| 1.5 mVpp | 1862.0 counts |
| 2.0 mVpp | 2482.0 counts |

| 指标 | 实测值 | 要求 |
|---|---|---|
| 拟合斜率 | 1241.2000 counts/mV | — |
| 反推模拟增益 | **999.9902 V/V**（标称 1000） | 误差 0.001 % |
| 拟合优度 R² | **1.000000** | > 0.999 |
| 线性度误差 | **0.043 %FS** | < 1 % |
| 电极分辨率 | 0.8057 µV/LSB | — |

### 8.3 为什么必须先做中值滤波

`ecg_cal_plateau_mean()` 先对平台做 3 点中值滤波再取均值。
测试里注入单点 4000 码值的毛刺，均值结果不变（仍是 2000.000），
说明毛刺被完全剔除；若直接取均值，单点毛刺会带来 31 码值的偏差，
对应标定误差 2.5%。

## 9. 上行帧协议（`frame_protocol.c`）

### 9.1 帧格式

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `HDR0 = 0xA5` | 帧头字节 0 |
| 1 | 1 | `HDR1 = 0x5A` | 帧头字节 1 |
| 2 | 1 | `TYPE` | 高 4 位 = 协议版本(1)，低 4 位 = 帧类型 |
| 3 | 1 | `LEN` | 载荷长度 0~255 |
| 4 | 2 | `SEQ` | 滚动序号，小端，65535 回绕 |
| 6 | LEN | `PAYLOAD` | 载荷 |
| 6+LEN | 2 | `CRC16` | CRC-16/CCITT-FALSE，覆盖 TYPE..PAYLOAD，小端 |

固定开销 8 字节；载荷最大 255 字节，整帧最大 263 字节。

**CRC 为什么不覆盖帧头**：帧头是同步字，接收端靠它找边界；
如果 CRC 覆盖同步字，那么“同步字被打错但其余部分正确”的帧会被判为
CRC 错而不是直接被丢弃，重同步逻辑会多绕一圈。不覆盖同步字可以让
格式错误与数据错误分开统计。

### 9.2 帧类型与载荷

| TYPE | 名称 | 载荷格式 | 长度 |
|---|---|---|---|
| 0x1 | `ADC_PACK12` | 样本数(2B) + 12 bit 偏移二进制打包（2 样本/3 字节） | 2 + ⌈1.5N⌉ |
| 0x2 | `ADC_DELTA` | 样本数(2B) + int16 基准 + int8 一阶差分（0x80 转义 + int16 绝对值） | 2 + 2 + M |
| 0x3 | `HR_REPORT` | flags + bpm_inst×10 + bpm_avg×10 + RR_ms + SQI + 保留 | 9 |
| 0x4 | `STATUS` | flags + 环形缓冲填充量 + 丢点计数 | 7 |
| 0x5 | `CALIBRATION` | 斜率×1000 + 截距×1000 + 线性度×100 + 增益×10 + R²×10000 + 点数 + flags | 16 |
| 0x6/0x7 | `ACK`/`NAK` | 被确认类型 + 被确认序号 | 3 |
| 0x8 | `HOST_CMD` | 上位机下行命令 | — |

**12 bit 偏移二进制编码**：心电微伏值是有符号的，而 12 bit 打包天然是
无符号的。约定 `code = value_µV + 2048`，即 1 µV 分辨率、±2048 µV 量程，
覆盖 1 mV R 波且留足裕量。超出量程时自动切换到 DELTA 编码（可表示任意
int16），并在测试中验证了这条回退路径。

**紧凑度实测（24 个心电样本一帧）**：

| 编码 | 载荷字节 | 相对 int16 |
|---|---|---|
| 原始 int16 | 48 B | 100 % |
| `ADC_PACK12` | 36 B | 75.0 % |
| `ADC_DELTA`（实测选中） | 35 B | 72.9 % |

整帧 45 字节（37 载荷 + 8 开销），60 s 端到端实测上行 **402 B/s**，
若直接发 int16 原始波形需要 500 B/s。460800 baud 下占用率约 0.9%。

### 9.3 帧同步状态机

接收端是**滑动窗口**同步器：窗口里保存候选帧的全部字节，
每收到一个字节就尝试解析；解析成功则消费整帧，任何失败都**只滑动 1 字节**。

```
        ┌──────────────────────────────────────────────────────┐
        │                                                      │
        ▼                                                      │
  ┌───────────────┐  收到 0xA5   ┌───────────────┐  LEN 已知  ┌──────────────┐
  │ HUNT_HEADER   │─────────────►│ RECV_HEADER   │───────────►│ RECV_PAYLOAD │
  │ 找 0xA5 0x5A  │              │ TYPE + LEN    │            │ 收满 LEN 字节│
  └───────────────┘              └───────────────┘            └──────┬───────┘
        ▲                                │                           │
        │                          版本非法/长度非法                  ▼
        │                                │                    ┌──────────────┐
        │                                │                    │ CHECK_CRC    │
        │                                │                    └──────┬───────┘
        │                                │                      CRC 错│  CRC 对
        │                                ▼                           ▼
        │                     ┌────────────────────┐        ┌──────────────┐
        └─────────────────────│ DISCARD / RESYNC   │        │ FRAME_READY  │
              滑动 1 字节     │ resync_slips++     │        │ 交付整帧     │
                              └────────────────────┘        └──────────────┘
```

**“只滑动 1 字节”这一条规则同时解决了 4 类问题**（都有测试用例）：

| 场景 | 行为 |
|---|---|
| 半包（一次 read 只给半帧） | 窗口保留已收字节，状态跨调用存活，下个字节继续 |
| 粘包（一次 read 给多帧） | 交付一帧后立即从窗口头部继续解析下一帧 |
| 帧内出现伪同步字 0xA5 0x5A | 该候选帧 CRC 失败 → 滑动 1 字节 → 真正的帧头重新被找到 |
| LEN 字段被打错 | 窗口有界（263 字节），等不到就强制重同步，后续帧照样恢复 |

实测：

- 1 个被篡改的帧后面紧跟 2 个正常帧 → 2 帧全部恢复，`CRC 错 = 1`
- 长度字段被改成 20（骗过长度检查）→ 后续 3 帧全部恢复
- 长度字段被改成 250（离谱值）+ 400 字节垃圾 → 后续 2 帧全部恢复
- 200000 字节纯随机数据 → **0 个假帧**
- 端到端 60 s 真实数据流，按 1/7/53/4096 字节的乱序分片喂入 →
  **704 帧全部解出，CRC 错 0，格式错 0，重同步滑动 0**

### 9.4 序号连续性

设备对**每一帧**（不分类型）分配一个单调递增序号。端到端测试逐帧校验
`seq == prev_seq + 1`，任何丢帧或重复都会被抓到——实测 0 次违例。

## 12. 已知限制与后续工作

诚实列出当前实现的边界：

1. **模拟前端只在 PC 桩里建模为“增益 + 基准搬移”，没有建模 0.05/0.5 Hz
   模拟高通和 100 Hz 抗混叠低通。** 这是刻意的保守做法：让数字滤波链
   面对最坏的 0.25 Hz 漂移，实测数字也确实把它压掉了 14 dB。
   代价是整链 R 波视在幅度下降约 10%（见第 6 节），
   真机上模拟通道先压一次后这个数字会更好。
2. **12 bit 打包量程 ±2048 µV**，超量程自动回落 DELTA 编码。
   对于 R 波 3 mV 以上的大信号会一直走 DELTA 分支，带宽上升约 10%。
3. `ecg_ring_reset()` 只在两端都空闲时安全（启动/错误恢复），
   运行中重置需要先停 DMA。
4. UART 采用“要么全收要么不收”的约定，短计数按真实溢出记账。
   真机驱动需要提供同样语义的发送环形缓冲。
5. `arm` 目标用 `arm-none-eabi-gcc 10.3.1` 把 6 个固件源文件全部编译成
   Cortex-M3 目标码且零告警（已实测通过），但本仓库不含启动文件和
   链接脚本，完整固件镜像需要配合 CubeMX 生成的启动代码。
6. HRV 指标（SDNN/RMSSD/pNN50）在合成的严格周期性信号上必然为 0，
   测试里断言的是“小于 2 ms”，真实数据上的有效性未做临床验证。
